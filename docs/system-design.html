At a glance

Phone onlyNo server, no account. Data stays in the phone's storage.
Two halvesA Kotlin listener collects alerts; the JavaScript app processes them when opened.
Strict auto-addA spend is added automatically only when card, cycle, category and rate are all certain.
Recomputed, not storedCashback for a whole cycle is recalculated after every change.

Where each part runs

SplitVCM is split across a process boundary. The native half is an Android NotificationListenerService written in Kotlin. Android keeps it running in the background, even when the app is closed. The app half is the React Native code, which only runs while SplitVCM is open. A small queue in between lets the two work at different times.

The listener does as little as possible. It skips apps you haven't allowed, and it skips text without an amount (Rs, INR or ₹) and a spend word (spent, debited, paid…). It also skips an exact re-post of a notification it already queued. Everything else, including the decision about what the alert means, happens in JavaScript, where it can be unit-tested.

The life of an alert

Every alert, whether it came from the phone's queue or was pasted on the Capture & Privacy screen, goes through the same three questions in inbox.js.

A worked example

Your HSBC Credit Card ending 5678 has been used for INR 899.00 at BIGBASKET on 14 Sep 2026 at 18:05. Available credit limit INR 1,20,000.
amount
₹899.00, the first amount in the text
cardLastFour
5678 → matches the HSBC Live+ card
merchant
BIGBASKET → keyword of the "10% groceries" category
occurredAt
14 Sep 2026 18:05 IST → cycle 10 Sep–09 Oct 2026

high: amount, merchant, card and date are all present

added automatically ₹89 cashback (10% of 899, rounded down)

An alert that goes to review isn't stuck there. When you add a card's digits, save a card or create a cycle, and each time the app opens, alerts waiting in review are checked again. Ones that are now certain move into their cycle automatically.

If the same spend then arrives by email ("…debited … towards BIGBASKET on 14 Sep 2026"), it has the same card and amount on the same day, so it's merged into the first record instead of being counted twice.

Why an alert goes to review

matcher.js collects every reason it has for doubt. A single reason is enough to hold the alert back. The review card shows each one in plain words, alongside a suggested group and category.

How cashback is calculated

Cashback is never added up as you go. computeCycle() in compute.js takes a cycle group's transactions, sorts them by date, and runs each one through the same five steps. It does this after every add, edit, move or delete. So a late email alert, a deletion that frees cap room, or a transaction moved to another cycle always gives the same result as if it had been entered in order.

  • Refunds are negative transactions linked to the original spend. They take back at most what that category has earned so far.
  • 0% / excluded categories and categories with a blank rate earn nothing. Every card has a 0% category, so excluded spends still show up in the totals.
  • Rounding is a setting on each card: round down each transaction, round down the cycle total, or no rounding.
  • Reward points (PhonePe SBI) are converted with an editable reward value, ₹1 per point by default.

How the data connects

A card is a template. Each billing cycle gets its own group, copied from the card when you tap "Create current cycle". Transactions live inside a group. A captured alert stays linked to the transaction it created, which is how the transaction editor can show the original SMS.

Why a group needs a card

An alert never names a group. It names a card ("HSBC Credit Card xx7342") and a date ("on 26/09/26"). So the app finds the group in two hops: the digits find the card, and the date finds that card's open group whose cycle covers the day. A manual group has no digits and no cycle dates, so no alert can reach it.

  • On an existing group: open it, tap Track this card automatically in its Card box, enter the last four digits and the cycle (a statement cycle with its start day, or calendar month), and tap Start tracking. Existing transactions stay.
  • On a new manual group: fill in the optional card fields when creating it.
  • From an alert: a review item for an unknown card has a Set up card •••• 7342 button that fills in the digits for you.
  • The first alert from each merchant still asks once, because a manual category has no merchant keywords. Keep Remember on, or add keywords to the category, and later alerts from that merchant are added automatically.

What happens when

A card spend on a normal day, from the phone buzzing to the number on the Cashback tab:

  1. The bank sends an SMS and Messages posts a notification. The Kotlin listener sees it within a second, even if SplitVCM is closed, and adds it to the capture queue.
  2. Later, you open SplitVCM. The app asks for your fingerprint, or your PIN if that fails.
  3. After unlocking, App.js syncs the capture settings to the listener, drains the queue, and runs every alert through the pipeline. Old captured text past its retention period is cleared at the same time.
  4. Alerts already waiting in review are checked again in case a card or cycle now exists for them.
  5. Clear alerts are added to their cycle silently. If any need review, one "Needs review" prompt appears with "Review now" and "Later".
  6. Whenever you return to the app, the same sync runs again. The prompt reappears only if a new alert went to review, not every time you come back from Android settings.

Privacy and security

  • No SMS permission. The app reads notifications only from apps on your allowed list, and only after you've agreed on the consent screen and granted notification access in Android.
  • Nothing leaves the phone. Android cloud backup is off (allowBackup: false). The JSON export is the only way data moves, and it leaves out captured text unless you ask for it.
  • Captured text expires. The original alert text is deleted 30 days after review (this is configurable), and resolved alerts are removed after 180 days. "Delete all captured text now" clears it immediately.
  • PIN in the keystore. The PIN is stored in SecureStore, you choose it on first run, and five wrong tries lock entry for 30 seconds. The old built-in PIN no longer works.
  • Card digits are optional. They're only used for matching and stay on the phone.
  • Installing the APK. Google Play Protect's fraud protection in India blocks sideloaded apps that read notifications when they're opened from a browser or file manager. Install with adb install from a computer, or turn Play Protect scanning off just for the install.
